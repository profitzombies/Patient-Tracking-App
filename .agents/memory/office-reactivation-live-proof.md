---
name: Office reactivation live proof
description: How the live reactivation harness proves an offboarded office reopens against the shared Supabase project, and the traps found (purge is two-phase, reopened_at survives a re-seal, retired-identity token trick, second-factor policy).
---
- Live suite: `pnpm --filter @workspace/thinnr-operations run test:office-reactivation-live` (validation command `office-reactivation-live`; needs the api-server workflow up at STAFF_API_BASE, default http://localhost:80; ~4 min). One office, two serial offboarding cycles: cycle 1 reactivates, cycle 2 purges one chart and asserts the 409 refusal.
- **Retired patient identity:** the seal deletes the patient's GoTrue user, so no bearer for it can exist. GoTrue admin create accepts an explicit `id`; recreate the user under its ORIGINAL auth_user_id (thinnr_claim metadata) and sign in — that is the only way to hit the `account_closed` → `reenroll_required` gate on `/patient-data/profile` live. `/claim/whoami` never emits reenroll_required.
- **Trap: purge is two-phase.** The privacy worker writes the tombstone, then deletes the patient row. Between them the preview counts the chart as BOTH destroyed and lapsed (retain_until ≤ now). Poll for "tombstone purged_at set AND patients row gone" before asserting preview counts or refusal wording.
- **Trap: `reopened_at` is not cleared by a later seal.** A chart reopened in cycle 1 and sealed again in cycle 2 keeps its cycle-1 reopened_at; assert it is unchanged, not null.
- Staff proof: the office owner is class `provider`, and the org policy requires a texted second factor for office managers, so owner login/start would return an SMS step — prove owner access with a direct GoTrue password sign-in. A plain `team_members` row (office_role staff) rides the real emailed-code rail: neutral + zero claim_verifications while offboarded, then start → inject known code hash → verify → GoTrue `/auth/v1/verify` → session that reads `/office/roster`. Use a `@thinnr-staff-check.com` address (one real email goes out).
- Cleanup adds to the offboarding harness: training_viewers/completions by email, team_members by provider, the member's provisioned auth user (found via team_members.auth_user_id), patient rows by both ids, tombstones by id list.
