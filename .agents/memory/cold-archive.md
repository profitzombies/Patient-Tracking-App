---
name: Cold archive to object storage
description: Decisions behind the nightly cold archive (HQ toggle + system job + ledger) that later archive/trim work must stay consistent with.
---

- **Day boundary and closure.** Archive days are UTC calendar days; only closed days (before today UTC) are ever archived, earliest first, bounded per run. **Why:** a day archived while still receiving rows could never be idempotent. **How to apply:** any future "trim live rows" decision must only touch days present in the archive ledger, never today.
- **Mark after everything lands.** A day's ledger row is written only after every per-table file AND the manifest are uploaded; the manifest object omits the generation timestamp so re-runs are byte-identical (the ledger row keeps `archived_at`). **Why:** the re-run test compares bytes, and "same content, same names" was the contract. **How to apply:** anything new in the manifest must be deterministic given the rows; put run-time facts in the ledger row instead.
- **Off = no-op, unconfigured = loud.** Toggle off tallies `skippedOff` and touches nothing; toggle on without `COLD_ARCHIVE_OBJECT_DIR` is refused at the HQ PUT, logged at boot, and thrown by the job every run (turns red after 2 consecutive failures). A malformed knob throws at boot. **Why:** a silently skipped nightly archive would look healthy for months. **How to apply:** keep the knob check inside the job, not only at the UI seam.
- **"Subscription changes" = `billing_subscriptions` rows keyed by `updated_at`** (there is no subscription history table). Other tables key on `created_at`. **How to apply:** if a subscription history table appears, add it as its own archive table rather than changing this one's key (would change already-archived day contents).
- **Threshold alert only counts while enabled.** Red = repeated failed runs, amber = backlog > 45 days; with the toggle off the evaluator emits nothing whatever the ledger says.
- **Test seams.** The archive source is an interface (real-PG suite backs it with psql; job suite uses memory store); route suites that factory-mock `lib/objectStorage` needed the shared thresholds reader stub (`coldArchive: async () => null`) added to their fake readers — a new default reader in `readPerformance` breaks every suite that passes a partial readers object.
- **Live schema:** `system_cold_archive_days` has RLS on with no policies (service-role only, intended; advisor INFO only). The `verify-org-policies` web script needs its explicit `process.exit(0)` — rendered screens leave pollers armed and the process otherwise hangs after passing.
