Rule: Patient-facing THINNR program wording (phases, foods lists, instructions, knowledge-base Q&A) must be quoted exactly from the verbatim archive under docs/thinnr-program/ — never paraphrased, summarized, spell-"fixed", or reordered. Apparent typos are intentional-to-preserve. The source PDF/paste beats any transcription if they disagree.

**Why:** The program is an official medical protocol and the owner required exact official wording for all downstream use (features, guidance, seeding). The originals contain oddities (stray parens, spacing like "6- 24 hours") that must survive copying; silent "corrections" are the failure mode.

**How to apply:** When a feature or seed needs program text, read the archive files instead of writing from memory. Mind the page-numbering offset (printed footer = PDF page + 1). If a page's text seems missing from the transcription, check a render of the PDF page — one page's food tables exist only as graphics and live in a bracketed appendix of that page block. When transcribing from renders, confirm small glyphs (e.g. ½ vs ⅓ fractions) from 600-dpi crops — a 200-dpi read once got a food amount wrong.

Structured program data: when program wording is turned into machine-readable data (e.g. the mobile app's approved-foods list), every verbatim string must be guarded by an automated check that whitespace-normalizes each string and asserts it appears as a substring of the archive file, plus count tripwires (bullets/table rows/total items) so silently dropped or added items fail loudly. Re-run the check after any edit to such data (mobile: `test:approved-foods` script; it also runs automatically as the `approved-foods` validation command alongside `demo-parity`). Curly quotes, en-dashes, and ½ glyphs must be encoded exactly — a plain-ASCII rewrite fails the check by design. UI must never pipe verbatim strings through case-transforming components (e.g. auto-uppercasing section headers).

**Machine-verifying quoted strings:** after building any content module that quotes the archive, verify every string with a script instead of trusting eyeballs: strip `--- Page N ---` and `Copyright © 2025 SlimCell N` lines from the archive, resolve its end-of-line hyphenations case by case (soft breaks like "de-/signed" join to "designed"; real compounds like "science-/backed" keep the hyphen), collapse all whitespace to single spaces on both sides, then assert each module string is a substring. Node ≥23 runs erasable-syntax .ts modules directly, so the script can import the real content module — keep such modules free of app imports. Curly apostrophes/quotes, en/em dashes, and preserved typos ("ofsystemic", "UNLESS is it", "The Thinner homeopathic medication", the stray period in "Nutrition Strategy. Approved Selections") are exactly what this catches.
